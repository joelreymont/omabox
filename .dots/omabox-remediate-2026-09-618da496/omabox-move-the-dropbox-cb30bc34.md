Problem: src/dropbox.rs and src/auth.rs hand-write every Dropbox request, response, and error tag over ureq; the review found timeouts, listing edge cases, error-shape mismatches, and header encoding bugs there, and the fake server tests prove the hand-written shapes rather than the documented API. Decision: adopt dropbox-sdk 0.20 (default-features off, features dbx_files, dbx_users, sync_routes) for all types and routes while implementing its HttpClient trait over our own ureq agents in a new src/transport.rs. Design: docs/remediation-2026-09.md section J (the contract), plus the E and I notes it references. Acceptance: Cargo.toml/Cargo.lock add dropbox-sdk with exactly those features and no bundled HTTP client; src/transport.rs implements HttpClient + UserAuthClient + NoauthClient with endpoint prefix mapping onto DropboxEndpoints (fake server reachable), Dropbox-API-Arg escaping of every byte outside 0x20..=0x7E, per-request-kind timeouts proven by behavioral tests against the fake with injected short constants (Rpc/OAuth global bound; Upload body-idle with finish response bound of one hour; Download header bound plus body-idle; LongPoll global = timeout + 90 s jitter + grace), status returned unchanged, Dropbox-API-Result and Content-Length copied, body streamed never drained, Range validation inside execute (200 for a ranged request, missing or mismatched Content-Range => typed transport error), token() and update_token() refreshing through oauth2::Authorization with a single refresh under a lock so concurrent workers never double-refresh, path_root() serialized PathRoot; src/dropbox.rs keeps DropboxClient's engine-facing API and calls sync_routes::files and users, deletes every hand-written request/response struct, post_api, authorized_post, find_mutation_rejection, status_failure, ascii_json, http.rs; MutationRejection and all classification match SDK enums exhaustively with no wildcard except the SDK Other variants mapped to a dedicated Unknown rejection; DropboxError is the classification surface listed in section J; uploads use one reused 32 MiB buffer with files above UPLOAD_SESSION_CHUNK_BYTES through sessions; UPLOAD_SESSION_MAX_BYTES = 350 GB; src/auth.rs keeps secret-tool storage and drives OAuth through the SDK (PKCE, ShortLivedAndRefresh, from_auth_code, obtain_access_token, from_refresh_token); the daemon no longer restarts a session on 401 (refresh failure is a typed authentication error); carry over from the superseded client change rsxorptv (workspace .jj-ws/omabox-tighten-dropbox-client-2a6b649a): RetriedTransport and UnverifiedMutation chained errors with the original as source, UploadedContentMismatch on the direct upload/finish path only, auth.rs child handling with CredentialCleanup and EPIPE status, ProgressReader::complete, drop-not-drain, and their tests; do not carry http.rs, per-phase timeouts, or HeaderNumber; the fake server emits .tag first and gains documented 409 bodies where tests need them; AGENTS.md and README describe the SDK-based wire layer; every existing fake-Dropbox and unit test passes or is updated with a stated reason. Files: Cargo.toml, Cargo.lock, src/transport.rs, src/lib.rs, src/dropbox.rs, src/auth.rs, src/bin/omaboxd.rs, src/bin/omabox.rs, tests/dropbox_fake.rs, tests/dropbox_live.rs, AGENTS.md, README.md. Verify: cargo fmt --check; cargo clippy --all-targets -- -D warnings; cargo test. Depends: canonical. Ownership: Dropbox transport and wire types. Claim: unassigned.
