Problem: src/dropbox.rs and src/auth.rs hand-write every Dropbox request, response, and error tag over ureq; the review found timeouts, listing edge cases, error-shape mismatches, and header encoding bugs there, and the fake server tests prove the hand-written shapes rather than the documented API. Decision: adopt dropbox-sdk 0.20 (default-features off, features dbx_files, dbx_users, sync_routes) for all types and routes while implementing its HttpClient trait over our own ureq agents in a new src/transport.rs. Design: docs/remediation-2026-09.md section J (the contract), plus the E and I notes it references. Acceptance: docs/remediation-2026-09.md section J is the contract in full; in particular: dropbox-sdk pinned =0.20.3 with default-features off and features dbx_files, dbx_users, sync_routes, no bundled HTTP client, Cargo.lock committed; src/transport.rs implements HttpClient + UserAuthClient + NoauthClient over two ureq agents configured with http_status_as_error(false); exact-match endpoint mapping with deferred typed errors for unknown URLs; infallible set_header storing raw pairs validated in execute with case-insensitive replacement; Dropbox-API-Arg re-encoded per Unicode scalar value (surrogate pairs above U+FFFF, existing JSON escapes kept), never bytewise; the per-kind timeout table (Rpc/OAuth global; Download send_request + recv_body idle; Upload send_body idle + recv_response; Finish recv_response one hour with an always-empty finish body; LongPoll global = body timeout + 90 s + grace) proven by behavioral tests against the fake with injected constants; status returned unchanged, Dropbox-API-Result and Content-Length copied, body streamed except the three bounded error-body reads (429, 5xx with Retry-After, 422); RateLimitFailure/ServerBusy local errors taking the greater of body and header delay capped at MAX_RETRY_AFTER; path root required and 422 parsed from Dropbox-API-Path-Root-Error into typed UserAction errors; range rules exactly as section J (RangeIgnored, RangeMismatch, UnexpectedRangeStatus, RangeUnsatisfiable; Accept-Encoding identity; no bytes=0-); TokenState single-flight refresh keyed by generation with a by-value RefreshClient, rotation persisted to Secret Service before publishing, PendingPersistence on store failure, Rejected on invalid_grant, one explicit refresh on an initial InvalidAccessToken; explicit route arguments (Add + strict_conflict + content_hash for creates, Update(rev) + strict_conflict for replaces and finishes, parent_rev deletes, autorename false, rev-pinned ranged downloads); no batch mode; one min(file, 32 MiB) buffer per upload with all data appended before an empty finish; oversized files blocked with BlockReason::UnsupportedFileSize; the per-operation error mapping table implemented as exhaustive matches with dedicated Unknown outcomes for SDK Other variants and sources preserved; src/auth.rs OAuth through the SDK with Secret Service storage kept; the fake server writes .tag first through an explicit writer and uses documented 409 bodies; the daemon never restarts a session on 401; carried-over items from change rsxorptv (workspace .jj-ws/omabox-tighten-dropbox-client-2a6b649a) as listed in section J; AGENTS.md and README describe the SDK-based wire layer; every existing test passes or is updated with a stated reason; durable upload-session resumption is NOT in this dot (see the J-resume dot).
